    How it works

    An agent can make mistakes or fall for a prompt injection. That is why its limit lives in your smart account, not in a prompt, and why only your wallet can change it.

    • Your wallet owns the account. Each user gets an OpenZeppelin smart account whose address is derived from their G address. Rule 0 (Default) has a single Delegated signer: your G address. Adding or revoking agents, changing limits and withdrawing all need your wallet’s signature.
    • The service never holds the owner key. It prepares each operation and shows you its summary; you sign the transaction or authorization entry in Freighter, and the relayer submits it and pays the fee.
    • Each agent is a rule with its own key. A CallContract(USDC) context rule with one ed25519 agent key. The agent can call USDC and nothing else, and cannot touch its own rule or any other.
    • Each agent has an on-chain limit. A spending-limit policy allows N USDC per 17280 ledgers (~1 day). Going over fails with Error(Contract, #3221), and no prompt can get around that.
    • Agent keys are encrypted at rest. The service generates a fresh key per agent and stores it encrypted. It uses the key only to sign that agent’s payments (the AuthDigest checked in __check_auth).
    • API keys are stored hashed. An external agent connects to /mcp with Authorization: Bearer awk_…. The key picks the agent, is shown once, and can be revoked at any time.
    • Revoking is instant and on-chain. It sets the rule’s valid_until a few seconds ahead, after which the agent’s signatures stop passing. Restoring clears it.
    • Large chat payments need your approval (above 2 USDC). This off-chain check sits on top of the on-chain limit.
